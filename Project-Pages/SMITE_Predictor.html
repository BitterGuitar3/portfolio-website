About

The idea behind this project is to create a tool that predicts the likelihood of a team winning in SMITE based on various player, god, and item stats. The tool compares one team's stats against another team's to provide a rough prediction of the match outcome.

While my brother is the driving force behind this idea, he has been unable to contribute recently due to other life priorities. Despite this, I'm still making progress here and there, aiming to develop the project to at least learn something new—if not to completion.

The current version of the predictor offers a selection of 24 gods available during SMITE 2's close beta (using stats from SMITE 1 due to lack of access to updated data). Players can choose their teams, and the tool calculates the probability of one team winning based on a comparison of average stats for both teams. Right now, the tool uses only level 1 god stats and doesn't account for other factors like items or player skill.

Features and Mechanics

  • Team Composition:
    • The predictor allows users to choose from 24 gods, ensuring no duplicate gods on a team. After selecting their team compositions, users submit their choices.
  • Prediction Logic:
    • Once the team is selected, the website calls the server for the gods' stats and compares the average stats between the two teams.
    • The comparison is straightforward: for each stat category, the tool checks which team performs better and “ticks” a variable in favor of that team. After all calculations, the result shows which team is more likely to win based on their average stats.

What I Learned

  • Relearning Web Development Basics:
    • Before diving into the project, I had to relearn the basics of HTML, CSS, and JavaScript. These foundational skills were crucial for the front-end development of the tool.
  • Database Setup and Server Communication:
    • I also learned how to set up a basic database and connect it with the front-end. One of the most challenging parts was understanding server communication between the front-end and back-end. I'm used to sequential execution, but working with server requests required asynchronous thinking. The server takes time to respond to API requests, which created challenges in the timing of the calculations and sometimes caused errors. With some trial and error (and help from online resources), I was able to get things working.
  • Networking Basics:
    • Although this project is relatively simple, it gave me exposure to the basics of networking and asynchronous code execution. This knowledge will be valuable when I eventually tackle multiplayer game development, such as for a WW2 FPS shooter I'm working on with a friend. Networking will be crucial when it comes time to implement multiplayer functionality in the game.

Reflection

This project may not have gone in-depth or turned into something complex, but it laid the foundation for future projects involving server communication, databases, and predictive algorithms. It also provided insight into networking—an area I'll need to focus on for future multiplayer game development.

Though there's still a lot to be done before this tool reaches its potential, it has been a great starting point for learning about the web development stack and server-side programming.
