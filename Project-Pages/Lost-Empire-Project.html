Name: Lost Empire Project

Project Type: Prototype

Basic Info

  • Engine: Unity
  • Role: Gameplay Programmer
  • Timeline: 4.5 months
  • Team: Solo (demonstrating my contributions without breaking contract)

About

This ongoing project is being developed in collaboration with a small indie team. My primary contributions have been designing and programming the player controller and enemy AI systems. The project is under an NDA with Lost Empire, so this page focuses on a general overview of my work without revealing confidential details.

The player system is built on a finite state machine (FSM), which controls transitions between movement states and ensures consistent animation syncing and input handling. For AI, I initially implemented state machine logic but later transitioned to a behavior tree architecture to better support complex, scalable decision-making.

Features and Mechanics

  • FSM-Driven Player Controller: Player actions are handled via a state machine that manages walking, sprinting, crouching, jumping (including double jump), dashing, and pausing. Each state has adjustable parameters such as speed, force, and cooldowns.
  • Combat System: Players can aim down sights for precision, fire a ranged weapon, and reload depending on their current state. Pausing the game suspends physics and input processing globally.
  • Behavior Tree-Based AI: NPCs operate on a behavior tree architecture powered by a blackboard system. The blackboard accepts key-value pairs using generic methods, allowing flexible input and type-safe configuration of AI logic at runtime.
  • Dynamic AI Configuration: Each NPC is configured through four main blackboard inputs. The first one influences their overall behavior (e.g., hostile vs friendly), while the second defines its movement logic.
  • Navigation & Area Control: NPCs navigate the world using Unity's NavMesh system, with support for area masks and restricted zones. Some enemy types are equipped with basic detection logic for spotting the player, with plans to expand this into a faction-based awareness system

What I have Leared

This project has been instrumental in deepening both my technical and collaborative development skills. Working with a remote team has taught me how to communicate across time zones and cultures while staying aligned on shared goals.

From a technical perspective, I've gained hands-on experience with:

  • Designing and implementing gameplay logic using FSMs and behavior trees
  • Working with Unity's NavMesh system for AI pathfinding and spatial awareness
  • Applying polymorphism and inheritance effectively to reduce redundancy and improve scalability in both the player and AI systems
  • Using generics and type checking in systems like the AI blackboard to handle diverse data inputs safely and efficiently
  • Evaluating async patterns in C# through tasks, and ultimately adopting coroutines for greater control within Unity's lifecycle
  • Transitioning from an improvisational development style to a more structured workflow using flowcharts and diagrams to track complex AI relationships
