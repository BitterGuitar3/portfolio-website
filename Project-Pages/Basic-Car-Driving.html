About

This was my first Unity prototype, created during the Unity Learn Junior Programmer pathway. The goal was to learn and apply the fundamentals of movement, input handling, physics, and basic UI through a simple two-player driving game.

Each player controls a car using separate input schemes (WASD and arrow keys), with the ability to move forward/backward, rotate, and switch between different camera perspectives. I also added a basic speedometer UI using the car's velocity to simulate real-time feedback.

Features and Mechanics

  • Player controls: WASD for Player 1 and arrow keys for Player 2. Forward/backward movement and rotation based on real-time input.
  • Camera Switching: Each player can toggle between camera views (F for Player 1, Right Shift for Player 2)
  • Physics Integration: Cars are powered by Unity's Rigidbody system, including velocity-based calculations and basic collision handling.
  • Speedometer UI: TextMeshPro-based display updates in real time based on the Rigidbody's velocity, simulating speed and RPM feedback.

What I Learned

This prototype helped me estabish a solid foundation in Unity development. Key takeaways include:

  • Movement & Input: Implemented consistent movement using Input.GetAxis and Input.GetKey, while applying Time.deltaTime for frame-independent motion.
  • Local vs. World Space: Gained a practical understanding of object rotation and movement in different coordinate spaces.
  • Physics Programming: Manipulated Rigidbody components to simulate realistic force, mass, and motion.
  • UI Programming: Created dynamic UI using TextMeshPro and learned to bind in-game values (like velocity) to visual elements.

Reflection

As my first Unity-based coding project, this was an important step toward learning how to connect code, gameplay logic, and user feedback. It taught me the building blocks of player mechanics, helped reinforce OOP concepts, and showed me how to bring code to life is a 3D space.
