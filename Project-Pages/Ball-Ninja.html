About

Ball-Ninja is the final prototype in the Junior Programmer Pathway from Unity Learn, focused on introducing a user interface (UI) into Unity projects. The game is inspired by the popular mobile game Fruit Ninja, with the player slashing balls and avoiding skulls.

Players:

  • Select a difficulty level and try to score as many points as possible.
  • Earn points by clicking and swiping the mouse to hit balls, but must avoid hitting skulls.
  • Lose a life if a ball falls off-screen without being hit.

The game also features a title screen, score tracker, pause screen, and game over screen.

Features and Mechanics

  • Mouse-Controlled Gameplay:
    • The player uses only the mouse to play the game (click and swipe).
    • Balls and skulls spawn randomly from the bottom of the screen, and players need to swipe them by holding down the left mouse button.
    • A trail renderer shows the swipe path, and objects explode in colorful effects when hit.
    • Skulls explode with a black effect to indicate they should be avoided
  • User Interface (UI):
    • Title Screen: Allows the player to choose the difficulty and set the background music volume.
    • In-Game UI: Includes score tracking and the ability to pause and resume the game with the P key.
    • Game Over Screen: After losing, players can restart the game using a restart button.

What I Learned

The key learning points from this project include:

  • Implementing Mouse-Based Swiping:
    • The swiping mechanic was tricky. To achieve this, I created an invisible object with a box collider and a trail renderer.
    • The object moves with the mouse cursor when the left mouse button is held down, and a boolean variable controls when the swipe is active.
    • The trail renderer takes care of drawing the swipe path, providing a smooth visual effect for the player.
  • Building a Functional UI:
    • Buttons: I learned that UI buttons in Unity don't always need a custom script. A button just needs a reference to an object and a function it can trigger when clicked.
      • For example, difficulty buttons call a function via button.onClick.AddListener(function) to change game settings when clicked.
      • To make a button interact with a different script, the function being triggered needs to be public
    • Scene Management: I also learned how to use SceneManager.LoadScene() to reload the scene when the game is restarted. However, this doesn't save things like music volume, so the next challenge is learning how to persist settings across game resets.
  • Managing Game Flow:
    • Developed systems for pausing, resuming, and restarting the game, with the player being able to navigate through the game using simple UI interactions.

Reflection

Building Ball-Ninja helped me understand the importance of integrating a UI to make games feel more complete and interactive. The most rewarding part of the project was learning how to create a fully functional UI that supports a seamless game flow, from difficulty selection to pausing and restarting the game. The project also introduced me to the idea of saving and persisting settings, which is the next step in making games more user-friendly.
